# 逐行重复帧节奏恢复

输入一段由**低帧率素材重复输出**而成的高帧率视频，估计源画面的更新节奏，去除人为复制产生的重复帧，并按**原始事件时间**重新封装出时长正确、音画对应的新视频。

> **图形入口（节奏恢复主界面）**
>
> ```bash
> npm install
> npm start
> ```
>
> 浏览器打开 <http://127.0.0.1:4173/>。片段选择、节奏相位与判断依据、运动分析播放器、逐候选帧解释和重封装结果都在这个页面里。

---

## 它解决什么问题

低帧率源（如 12 fps 动画）被提升到 30 fps 时，制作者会把同一画面连续输出多帧。直接播放时画面“卡顿”，但这些重复帧让文件看起来是 30 fps。本工具做到：

1. **估计源画面更新节奏** —— 不是“每 N 帧删一帧”，而是拟合一个声明的有理节奏（例如 30/12 = 2.5 → `[2,3]` 交替），并给出**相位**（每个周期从哪一帧开始）。
2. **区分“复制重复”和“真实静止”** —— 真实停顿的画面同样连续多帧不变，但它的长度超出节奏的最大重复数，且持续时间足够长；这类区间保留完整时长，**绝不压缩静止时间**。
3. **压缩噪声下仍能判定** —— 重复帧经有损编码后不再逐像素相同，因此判定结合**差异幅度 + 空间结构 + 运动补偿增益**，而不是文件哈希。
4. **证据不足时保留多解** —— 差异落在阈值附近、或全片画面几乎不变时，标为不确定区并保留，宁可少删也不误删。
5. **交付真正重封装的结果** —— 逐帧按原 PTS 重编码，保留原音轨（流复制，比特一致）。**不是**只改容器帧率标签。

图形界面的结果区会列出每个**保留帧的源帧号、原事件时间、显示开始/结束与显示时长**，全部来自实际运算；异常（时长不符、缺音轨、节奏低匹配）会直接显示在“恢复结果”和“节奏相位与判断依据”面板中。

## 快速开始

```bash
npm install          # 安装 ffmpeg/ffprobe 与 Playwright
npm start            # 启动图形界面 → http://127.0.0.1:4173/
```

首次启动时，内置测试素材会在后台生成到 `data/samples/`（也可手动 `npm run fixtures`）。

界面流程：

1. 在左侧“素材”选择内置测试素材，或上传本地视频。
2. 设定片段开始/结束（默认整段）。
3. 点“分析节奏”。右侧“运动分析播放器”可切换 **原片 / 保留帧 / 结果** 三种模式，时间轴以颜色区分保留帧、被丢弃的复制帧、真实静止与不确定帧。
4. 在“节奏相位与判断依据”查看估计源帧率、重复模式、相位条、阈值证据与候选节奏表。
5. 在“区间与候选帧解释”查看每个区间的判断依据与每个被丢弃候选帧的原因。
6. 在“节奏推断追踪与复制模式诊断”对比“检测端复制证据”和“从恢复节奏反推的候选删帧”，确认结论属于证据充足、观测不足还是实现误判；展开后逐区间列出删除依据、候选支持与源帧映射。时间轴上的橙色虚线标出相位变换位置。
7. 点“恢复并重封装”生成结果；“恢复结果”区显示实际保留帧、播放时间、对应原因、音轨状态，并可下载。

## 支持声明的有限节奏类型

初版只支持显式声明的源帧率假设（自动检测在其中择优）：

| id | 源 → 输出 | 重复模式 |
|----|-----------|----------|
| `src30` | 30 → 30 | 无复制 |
| `src25` | 25 → 30 | `1,1,1,1,2` |
| `src24` | 24 → 30 | `1,1,1,2` |
| `src20` | 20 → 30 | `1,2` 交替 |
| `src15` | 15 → 30 | `2` |
| `src12` | 12 → 30 | `2,3` 交替 |
| `src10` | 10 → 30 | `3` |
| `src8`  | 8 → 30  | `3,4` 交替 |
| `native` | 源帧率 = 输出帧率 | 无复制（仍可能保留真实停顿） |

模式由 Bresenham 分布 `floor((s+1)·n/d) − floor(s·n/d)` 生成，其中 `n/d = outFps/srcFps`，分母上限 64。界面“节奏假设”可锁定某个类型；锁定后若与画面证据冲突，会保留可疑区间并提示，而不是强行删除。

## 判断方法与证据

对相邻两帧计算三项独立证据（`src/analysis/features.js`）：

- **差异幅度**：8×8 块上的平均绝对亮度差（`diff.mean`）。
- **空间结构**：块差异的 90 分位 `blockP90`，用来区分“局部内容变化”与“整体噪声”。
- **运动补偿增益**：整数像素全局平移搜索后的残差下降比（`motionGain`），捕捉真实运动。

`src/analysis/cadence.js` 用 Otsu 在“复制簇”和“更新簇”之间求自适应阈值，并把判定分成三种证据模式：

- `bimodal`：存在明显复制簇与更新簇 → 正常判定；
- `no-copies`：差异分布单峰，没有成规模复制 → 不删除；
- `all-static`：全片几乎不变 → 全保留并标为多解。

**真实静止**：连续不变长度超过当前节奏的最大重复数、且持续时间 ≥ 0.32 秒的区间，视为真实停顿，保留首帧并按其原显示时长呈现。**不确定区**：差异落在阈值附近、差异大但缺结构/运动证据、或与模型不符的区间，全部保留并写明原因。

## 节奏推断追踪与复制模式诊断

`src/analysis/trace.js` 在分析完成后构建一份**只读追踪**：它消费已经算出的逐帧证据、区间和节奏拟合结果，**不删除帧、不修改决策、不改变待分析序列**（对同一份分析重建追踪，区间处理与删除集合逐项一致）。追踪沿复制模式诊断建立执行证据链，回答“这个结论是观测不足，还是实现误判”。

追踪对比两条路径：

- **检测端复制证据**：`transition.isChange=false 且 uncertain=false` 的帧，即逐帧证据直接判为复制。
- **从恢复节奏反推候选删帧**：拟合出的模式（如 24→30 `[1,1,1,2]`）在运行区匹配后，按相位应删除的复制候选。

面板显示两路的删除计数，以及“两路一致删除 / 仅节奏反推删除 / 仅检测判复制但未删”三项差异；出现差异时说明 `implementation-misjudgment` 的定位阶段。

**根因分类**（面板顶部的判词）：

| 类别 | 含义 |
|------|------|
| `sufficient`（证据充足） | 检测与节奏两条路径一致，源帧映射不变量全部通过，结论可靠。 |
| `insufficient-observation`（观测不足） | 短静止保持与编码复制在像素上完全一致，无法区分。典型表现是相位在**非静止边界**处重排（`static-vs-copies`），或全片几乎不变（`all-static`）、节奏多解（`ambiguous-fit`）。此时删除不改变时间轴，但“复制重复”的归因不可靠，应保留并标为不确定。 |
| `implementation-misjudgment`（实现误判） | 出现不变量违例，或存在**只由节奏反推、没有任何检测端复制证据支撑**的删除。 |

**执行证据链**：`classify → runs → fit → decide` 四个阶段，每个阶段给出通过/失败与关键量（证据模式与阈值、区间数、最佳假设、保留/删除帧数）。

**候选支持与源帧映射**：每个声明的节奏假设列出得分、相位段数、隐含的保留/删除帧数；相位段标明是否因静止边界而重置。逐区间表（`detection` / `cadence` / `mapping`）记录内部复制证据、支撑来源（检测、节奏或两者）、以及该区间被删帧映射到的更早保留源帧；源帧映射不变量要求保留源帧严格递增、每个被替换帧映射到更早的保留源帧、显示时间覆盖片段。

**区分原因**：追踪记录静止段（`static` 与 `unexplained-long`）以及相位变换及其原因（`static-hold` 或其他）。相位在同一段内保持单一偏移说明节奏稳定；在**非静止边界**反复重置相位，正是静止保持被误当成周期复制的位置——这也是界面上时间轴橙色虚线的落点。

诊断输出**有界**：转场、区间链接、映射、删除证据与日志行都经等步长采样（默认上限见 `DEFAULT_BUDGET`），同时保留真实总数，因此大素材不会让日志或面板失控。命令行 `analyze --json` 的 `diagnosis` 字段与 `traceLogLines()` 输出同一份追踪。

对照片段 `splice_static`（剪接 + 静止保持）与 `splice_motion`（相同节奏与剪接，但后段为真实运动）用于核验：两者删除集合相同，追踪却分别给出 `insufficient-observation/static-vs-copies` 与 `sufficient/cadence-confirmed`。

## 输出保证

- **保留原事件时间**：每个保留帧的时间戳等于它在原片中的位置，显示时长由下一保留帧（或片段结束）决定，总时长与片段一致。
- **不是改标签**：输出帧的 PTS 间隔为非均匀（如 `2/30` 与 `3/30` 交替），证明是逐帧重排而非修改容器帧率。
- **音轨对应**：原音轨以 `-c:a copy` 流复制写入，PCM/WAV 情况下比特一致，声音事件与画面事件时间对齐。
- **每个丢弃候选都有解释**：区间表与逐帧明细列出丢弃原因、所属区间、相位、置信度。

实现细节（`src/util/render.js`）：按保留帧抽 PNG → concat 列表以 `option framerate 90000` 与逐项 `duration` 精确控制显示时长 → `-bf 0` 避免 B 帧破坏时长传递 → 尾部幻影帧 + `-c copy -t` 精确裁掉 → 流复制原音轨。

## 命令行（仅辅助）

命令行只用于节奏恢复的**分析与批处理**，不替代图形界面的交互式相位/证据查看与播放：

```bash
node src/cli.js presets
node src/cli.js analyze <视频> [--start 0] [--end 4] [--preset auto] [--json]
node src/cli.js render  <视频> [--start 0] [--end 4] [--preset auto] [--out out.mp4] [--no-audio]
```

`analyze` 打印估计节奏、相位、证据水平、每个区间的处理与原因，并附带“节奏推断追踪与复制模式诊断”摘要；`analyze --json` 的 `diagnosis` 字段给出根因、路径对比、候选支持、相位故事与有界日志。`render` 会分析后直接重封装。交互式的运动分析播放器、候选帧解释与结果预览请使用图形入口 <http://127.0.0.1:4173/>。

## 测试

```bash
npm run fixtures     # 生成内置测试素材（含清单）
npm test             # node:test 自动化测试
```

测试素材覆盖：`alt23`（12→30 `[2,3]`）、`alt23_static`（含 1 秒真实静止）、`alt23_noisy`（叠加噪声 + 高压缩，复制帧逐像素不同）、`pulldown2430`（24→30 `[1,1,1,2]`）、`const3`（10→30 `[3]`）、`native30`（原生 30 fps 无复制 + 真实静止）、`static_only`（全静止）、`splice_static`/`splice_motion`（相同节奏与剪接，后段分别为静止保持与真实运动）。

自动测试核验：

- 估计源帧率与重复模式正确；
- 保留帧落在源画面更新处（与素材清单 `outputToSource` 对照）；
- 保留时间覆盖全片时长，静止段不被压缩；
- 无复制素材不得删除任何真实运动帧；
- 全静止时保留全部帧与多解；
- 噪声素材中复制帧差异非零、但仍显著低于更新帧；
- 重封装后帧数、PTS 非均匀间隔、画面内容条码、音轨 MD5 与期望一致；
- 节奏推断追踪只读（重建后决策与删除集合不变）、有界（采样后总数保留）、不伪报；
- 对照片段结论正确：`splice_static` → 观测不足（`static-vs-copies`），`splice_motion` → 证据充足。

界面端到端冒烟测试（需 Playwright 浏览器可用）：

```bash
node test/e2e/smoke.mjs
```
